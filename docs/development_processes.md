## 1. Workflow в репозитории

Разработка ведется по стандартному **git flow**:

**`main`** - содержит в себе последний релиз приложения.

**`develop`** - основная ветка, в которой ведется разработка. 

**`RI-{номер задачи + название ветки}`** - ветки задач

## 2. Пул реквесты

### 2.1. Название.

Название должно включать имя таска из Weeek и/или краткое описание на русском, одним предложением.

Пример: `RI-969340 ImageButton. Общая кнопка с иконкой`

Если создается цепочка пул реквестов, то в названии отражается фича к которой относится этот пул реквест и номер пул реквеста в цепочке.

Пример: `[1] RI-969341 Верстка экрана`

Если в одном МРе несколько задач, то в заголовке МРа, нужно перечислить номера всех задач.

Пример: `RI-964924 RI-942349 Добавлены ячейки для списков`

### 2.2. Лейблы.

На проекте принято использовать лейблы, чтобы можно было удобно фильтровать и ревьюить PR-ы. Все используемые лейблы описаны в GitHub.

### 2.3. Assignee

В качестве assignee выбрать себя

### 2.4. Текст

Если это фича - требуется кратко описать, какая часть функциональности была реализована в рамках работы над таском. 
Для бага нужно описать причину, как он был исправлен и шаги воспроизведения, если они как-то отличаются от описанных в таске, 
либо если обнаружились дополнительные кейсы или шаги. Без подробностей из задачи, но с указанием особенностей, которые могут 
броситься в глаза или на которые стоит обратить внимание при ревью кода.

### 2.5. Вложения

Принято прикреплять видео, скриншоты или логи в зависимости от фичи.

Видео - для переходов навигации, переключения состояний или другой UI логики.
Скриншоты - изменения верстки, текстов лейблов или другие простые изменения.
Логи - можежет понадобиться, если добавиться взаимодействие с сервером.

Все перечисленные вложения можно прикреплять в двух видах - до и после, если это требуется и позволит легче понять, что таск был выполнен правильно.
Во всех случаях стоит руководствоваться здравым смыслом, при сомнениях что лучше прикрепить можно посоветоваться с командой или лидом.

### 2.6. Шаблоны

Для ускорения и стандартизации оформления пул реквестов в проект добавлен шаблон, который 
содержат структуру для оформления и чеклист для проверки все ли готово для создания пул реквеста.

### 2.7. Markdown basic syntax

Для оформления бывает полезно использовать дополнительные средства разметки, позволяющие легче воспринимать информацию.
https://www.markdownguide.org/basic-syntax/

## 3. Процесс ревью

- В reviewers указываются все разработчики, то есть используем процесс кросс-ревью.
- Для слития PR-а необходимо получить два аппрува.
- PR-ы сливаются лидом проекта
