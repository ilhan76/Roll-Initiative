# Модели данных

- [1. Маппинг data-domain слоя](#1-маппинг-data-domain-слоя)
- [2. Маппинг Ui моделей](#2-маппинг-ui-моделей)

Виды моделей в проекте:
- Сущность базы данных
  - `{Name}Entity` - сущность БД
- Доменная - именуется без дополнительных приставок
- UI-модель
  - `{Name}Ui` - ui-обертка для отображения

## 1. Маппинг data-domain слоя 

- Используются для преобразования моделей из одного слоя в другой
- Не должны содержать никакой другой логики 
- Маппинг происходит в `DataDource`
- Расположение маппера
  - В директории `./mapper` создается файл с суффиксом `Mapper`
  - Внутрь файла помещается top-level extension функция (`toDomain` или `toEntity`)

## 2. Маппинг Ui моделей

- Используются для преобразования моделей из одного слоя в другой
- Может содержать логику
  - Если для маппера требуются сторонние зависимости, то создается класс поставлять его необходимо через `DI`
- Расположение маппера
  - Маппер требует сторонние зависимости
    - В директории `./mapper` создается **класс** с суффиксом `Mapper`
    - Через DI в этот класс поставляются необходимые зависимости
    - Внутри класса создается фукнция, принимающая domain модель и возвращающая UI
  - Маппер не требует зависимости
    - В директории `./mapper` создается **файл** с суффиксом `Mapper`
    - Внутрь файла помещается top-level extension функция (`toUI`)
